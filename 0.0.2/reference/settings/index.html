Settings¶

uc-server and uc read the same settings. Each setting is a key in a [group] table of uc.toml, and an environment variable UC_<GROUP>_<KEY>: enabled in [auth] is UC_AUTH_ENABLED.

# uc.toml
[server]
data_dir = "/var/lib/uc"

[db]
url = "postgresql://uc@postgres.example.com:5432/uc?sslmode=verify-full"

[auth]
enabled = true
admin_principals = ["alice@example.com"]

The same with variables:

export UC_SERVER_DATA_DIR=/var/lib/uc
export UC_DB_URL='postgresql://uc@postgres.example.com:5432/uc?sslmode=verify-full'
export UC_AUTH_ENABLED=true
export UC_AUTH_ADMIN_PRINCIPALS=alice@example.com

Where the settings come from¶

A setting takes its value from the first of:

  1. a command-line flag, such as --port;
  2. its environment variable;
  3. uc.toml;
  4. its default.

The settings file is the file of --config, else the file that UC_CONFIG names, else the first uc.toml in the working directory or a folder above it. Without a file, the variables and the defaults apply.

Values¶

  • A key that is not a setting is an error, in the file and in a variable of a group. Errors name the setting, its variable and the file: auth.enabld (UC_AUTH_ENABLD): unknown field.
  • Other UC_ variables are not settings, such as UC_CONFIG.
  • Variables are text. The server reads numbers and booleans from the text. An empty variable is unset.
  • A duration is text such as 30s, 5m, 24h or 5d.
  • A list is a TOML array, or text with commas: UC_AUTH_ADMIN_PRINCIPALS=alice@example.com,bob@example.com.

Cloud identities and locations¶

[identity.<cloud>] is how the server signs in to AWS, Azure or GCP. A [locations.<name>] gives the paths under its URL an identity, when no external location covers them. Cloud storage tells how they work with external locations, with examples per cloud.

The variables of these tables include the cloud or the name: UC_IDENTITY_AWS_SECRET_KEY is secret_key in [identity.aws], and UC_LOCATIONS_ANALYTICS_URL is url in [locations.analytics]. A name has only lowercase letters and digits, and at least one letter: the server reads a name of only digits, such as UC_LOCATIONS_0_URL, as a list index.

readiness_interval UC_SERVER_READINESS_INTERVAL 5s How often /readyz checks the database.

[auth]¶

Setting Variable Default Description
Authorization Sign-in and privilege checks for the API, and the first users and admins.
enabled UC_AUTH_ENABLED false Require sign-in, and check privileges.
admin_principals UC_AUTH_ADMIN_PRINCIPALS none The emails of the admins, besides the metastore's owner: see Privileges.
users none none [[auth.users]]: the users that the server makes at each start when they are missing. Only in uc.toml. See The first users.
engine UC_AUTH_ENGINE grants What decides each privilege: grants, cedar (see Cedar policies) or opa (see Open Policy Agent). cedar and opa need enabled = true.
cedar_policies UC_AUTH_CEDAR_POLICIES none With engine = "cedar": files of Cedar policies, on top of the default policy.
opa_url UC_AUTH_OPA_URL none With engine = "opa": the URL of the policy's decision in OPA's data API, such as http://opa:8181/v1/data/uc/authz.
opa_timeout UC_AUTH_OPA_TIMEOUT 5s With engine = "opa": how long one decision may take.
opa_token_file UC_AUTH_OPA_TOKEN_FILE none With engine = "opa": a file with the token that the server sends to OPA as Authorization: Bearer <token>, for an OPA that takes tokens. See Protect OPA.
trusted_proxies UC_AUTH_TRUSTED_PROXIES none The proxies in front of the server that add the client's address to X-Forwarded-For, such as an ingress: CIDRs or addresses. The limits per client count by that address. See Behind a proxy.
Tokens The server's own tokens, and the identity providers whose tokens it takes.
signing_key_file UC_AUTH_SIGNING_KEY_FILE none The PEM file of the RSA keys of the server's tokens, newest first: the first signs. Without it, the server makes a key in memory at each start. See The signing key.
access_token_timeout UC_AUTH_ACCESS_TOKEN_TIMEOUT 24h The life of the server's access tokens.
cookie_timeout UC_AUTH_COOKIE_TIMEOUT 5d The life of the UC_TOKEN cookie of the web UI.
issuers none none [[auth.issuers]]: the identity providers whose tokens the server takes, at the token exchange and, with direct, on every request. Only in uc.toml. The keys follow.
Web UI sign-in How users sign in to the web UI. The settings of each mode follow.
mode UC_AUTH_MODE none The web UI's sign-in: none, oidc or forward.
OpenID Connect mode = "oidc": the server signs users in with an OpenID Connect provider.
public_url UC_AUTH_PUBLIC_URL none The server's external URL. The provider returns the browser to <public_url>/auth/callback, and with oidc_end_session to <public_url>/ after "Log out". The URLs in SCIM answers and Delta Sharing profiles start with it, in every mode; without it, they start with the URL that the client called.
oidc_issuer UC_AUTH_OIDC_ISSUER none The OpenID Connect provider's issuer.
oidc_client_id UC_AUTH_OIDC_CLIENT_ID none The OAuth client.
oidc_client_secret UC_AUTH_OIDC_CLIENT_SECRET none Its secret; none for a public client.
oidc_scopes UC_AUTH_OIDC_SCOPES openid email profile The scopes that the server asks for.
oidc_end_session UC_AUTH_OIDC_END_SESSION false "Log out" also ends the provider's session: see OpenID Connect.
Auth proxy mode = "forward": an auth proxy in front of the server signs users in, and sends their email in a header.
forward_trusted_proxies UC_AUTH_FORWARD_TRUSTED_PROXIES none The auth proxies whose headers count: CIDRs or addresses.
forward_email_header UC_AUTH_FORWARD_EMAIL_HEADER Remote-Email The header with the user's email.
forward_user_header UC_AUTH_FORWARD_USER_HEADER Remote-User The header with the user, without the email header.
forward_names_with_commas UC_AUTH_FORWARD_NAMES_WITH_COMMAS false A header value with a , is one name, such as the subject of a client certificate (CN=alice,OU=eng). Without it, such a value names nobody, as it could be the client's value with the proxy's added. Set it only when the proxy replaces the client's headers.
forward_logout_url UC_AUTH_FORWARD_LOGOUT_URL none The proxy's sign-out, where the web UI's "Log out" goes.

[[auth.issuers]]¶

[[auth.issuers]]
name = "entra"
issuer = "https://login.microsoftonline.com/<tenant>/v2.0"
audiences = ["<the API app's client id>", "https://uc.example.com"]
direct = true
principal_claims = ["preferred_username", "oid"]
client_claims = ["azp", "appid"]
groups_claim = "roles"
create_users = true
display_name = "{app_displayname}"
Key Default Description
name required A short name of lowercase letters, digits, - and _: the prefix of the principals it names without an email, such as entra:<oid>.
kind oidc oidc for an OpenID Connect provider; aws for AWS identities, whose signed GetCallerIdentity requests the server sends to STS.
issuer required The iss claim of its tokens, as they write it, with a trailing / if they have one; * stands for one DNS label of letters, digits and -, and in the host it needs two fixed labels after it. For aws, the URL of the STS endpoint, by default AWS's global and regional ones.
audiences required The aud that its tokens must carry; ["*"] accepts every audience, without direct; with direct, no *. For aws, the server id that the signed requests carry: the server's URL as clients call it; no *. Clients ask for the audience that is the server's URL.
accounts required for aws The 12-digit AWS accounts whose identities it takes.
direct false Take its tokens on every request, not only at the token exchange.
principal_claims ["email", "sub"] The claims that name the caller; the first present wins. An email names the user with that email; with an issuer with *, only when the token says email_verified = true. Any other value names the user <name>:<value>.
client_claims ["azp", "client_id"] The claims with an application's client id: the user whose externalId is <name>:<client id> is the application.
groups_claim none A claim whose values are names of groups the caller is in; a value counts when the server has the group <name>:<value>, such as entra:Writers. Not with an issuer that has *.
create_users false Make the user at its first request when it is missing.
display_name the principal The display name of a made user, with claims in braces.

Identity providers tells how a block names the caller.

Sign-in and authorization tells how these settings work together.

[identity.aws]¶

The identity that the server signs in to AWS with. It assumes the roles of storage credentials. Without keys, the server uses the credentials of the machine or pod where it runs: the AWS_* variables, the role of a Kubernetes service account, an ECS task role, EKS Pod Identity or an instance role.

Setting Variable Default Description
access_key UC_IDENTITY_AWS_ACCESS_KEY the credentials where the server runs The access key.
secret_key UC_IDENTITY_AWS_SECRET_KEY the credentials where the server runs The secret key.
region UC_IDENTITY_AWS_REGION AWS_REGION, else AWS_DEFAULT_REGION, else us-east-1 The region of the STS calls.
arn UC_IDENTITY_AWS_ARN none The ARN of this identity, shown as unity_catalog_iam_arn on storage credentials, for the trust policies of their roles. A role here is also the one of aws_iam_role_arn = true; its trust policy must then allow the role itself.
endpoint UC_IDENTITY_AWS_ENDPOINT AWS The S3 and STS API of an S3-compatible store, such as MinIO or RustFS: http:// or https://. uc's table and volume commands use it too. See Cloud storage.

[identity.azure]¶

The identity that the server signs in to Azure with: a service principal, or a user-assigned managed identity. Without one, the server uses the credentials of the machine or pod where it runs: AKS workload identity, the AZURE_* variables, or the managed identity of the VM or App Service.

Setting Variable Description
directory_id UC_IDENTITY_AZURE_DIRECTORY_ID The service principal's tenant ID.
application_id UC_IDENTITY_AZURE_APPLICATION_ID The service principal's client ID.
client_secret UC_IDENTITY_AZURE_CLIENT_SECRET The service principal's secret.
managed_identity_id UC_IDENTITY_AZURE_MANAGED_IDENTITY_ID Or the resource ID of a user-assigned managed identity, from the instance metadata service.

[identity.gcp]¶

The identity that the server signs in to GCP with. Without a key, the server uses the credentials of the machine or pod where it runs, which Google calls Application Default Credentials: the GOOGLE_APPLICATION_CREDENTIALS file, gcloud's application default credentials, or the metadata server, such as GKE Workload Identity.

Setting Variable Default Description
json_key_file UC_IDENTITY_GCP_JSON_KEY_FILE Application Default Credentials A service account's JSON key file.
endpoint UC_IDENTITY_GCP_ENDPOINT Google The STS and IAM Credentials API of a GCP emulator, such as Floci: http:// or https://.

[locations.<name>]¶

A URL and the identity that reaches the paths under it, for paths that no external location covers. With authorization on, it serves only the paths that the admin wrote, storage.tables_root and storage.models_root; see Which location serves a path. The URL's scheme picks the cloud, and an entry holds exactly one identity of that cloud. When several entries cover a path, the one with the longest URL wins.

Setting Variable Cloud Description
url UC_LOCATIONS_<NAME>_URL all s3://bucket, abfss://container@account.dfs.core.windows.net or gs://bucket, with a path or without. Required.
region UC_LOCATIONS_<NAME>_REGION S3 The bucket's region, which Iceberg clients get. Without it, the server asks S3.
aws_iam_role_arn UC_LOCATIONS_<NAME>_AWS_IAM_ROLE_ARN S3 true for the server's own role, identity.aws.arn, or the ARN of a role that [identity.aws] assumes. Required for S3.
azure_directory_id UC_LOCATIONS_<NAME>_AZURE_DIRECTORY_ID ADLS A service principal's tenant ID, with azure_application_id and azure_client_secret.
azure_application_id UC_LOCATIONS_<NAME>_AZURE_APPLICATION_ID ADLS Its client ID.
azure_client_secret UC_LOCATIONS_<NAME>_AZURE_CLIENT_SECRET ADLS Its secret.
azure_managed_identity UC_LOCATIONS_<NAME>_AZURE_MANAGED_IDENTITY ADLS true for [identity.azure], or the resource ID of a user-assigned managed identity.
gcp_service_account UC_LOCATIONS_<NAME>_GCP_SERVICE_ACCOUNT GCS true for [identity.gcp], or the email of a service account that [identity.gcp] impersonates.
gcp_service_account_key UC_LOCATIONS_<NAME>_GCP_SERVICE_ACCOUNT_KEY GCS A service account's JSON key file.
